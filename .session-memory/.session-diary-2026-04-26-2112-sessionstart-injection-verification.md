## 设计限制与职责划分

### SessionStart vs Stop Hook

**职责差异：**
```
SessionStart Hook：
- 触发时机：会话启动（一次性）
- 作用：注入历史记忆（让AI知道之前做了什么）
- 更新频率：不实时更新
- 目的：节省重新探究时间

Stop Hook：
- 触发时机：每15次对话（持续性）
- 作用：保存当前会话进展（创建新日记）
- 更新频率：实时更新
- 目的：记录进展供下次注入
```

**协作关系：**
```
Stop Hook → 创建新session diary
↓
下次会话 → SessionStart Hook注入
↓
AI获得完整历史（包括上次Stop保存的内容）
↓
循环继续
```

### 设计限制的合理性

**为什么不实时更新SessionStart？**
1. **性能考虑**
   - 每次对话都注入历史会大量消耗token
   - SessionStart一次性注入更经济

2. **职责清晰**
   - SessionStart：启动注入（一次性）
   - Stop：持续保存（多次）
   - 职责分离，避免混淆

3. **实际需求**
   - AI启动时需要历史（SessionStart提供）
   - AI过程中需要保存进展（Stop Hook提供）
   - 两者配合满足需求

**这是设计限制，不是bug ✓**
