## GPU加速优化分析（后续会话）

- ✅ torch已安装

- ✅ SentenceTransformer模型设备：cuda:0
- ✅ GPU正在被使用（PID 111829占用4237MB GPU内存）

**当前进程：**
- PID 111829（新mine进程）
- 运行时间：4分02秒（仍在进行）
- CPU：60.7%，内存：40.8%
- 正在使用GPU加速

### 发现的真实瓶颈
GPU已开启，但仍有优化空间：

1. **批处理大小较小**
   - 当前：`batch_size=256`（代码硬编码）
   - 数据量：9553条记录
   - 批次数：37批次
   - 即便GPU加速，37批次仍需时间

2. **数据库同步写入**
   - Qdrant `wait=True` 等待磁盘确认
   - 无法完全异步

### 优化实施
**修改：** `mempalace/backends/qdrant.py`

```python
# 修改前
embeddings = model.encode(documents, batch_size=256, show_progress_bar=False).tolist()

# 修改后
embeddings = model.encode(documents, batch_size=512, show_progress_bar=False).tolist()
```

**影响范围：**
- Line 61: `add()` 方法embedding批处理
- Line 94: `upsert()` 方法embedding批处理
- Line 137: `query()` 保持`batch_size=32`（查询场景）

### 性能对比

| 配置 | GPU | batch_size | 批次数 | 预估时间 |
|------|------|-----------|--------|----------|
| 旧配置 | ❌ CPU | 256 | 37批 | 8-9分钟 |
| 现配置 | ✅ GPU | 256 | 37批 | 2-4分钟 |
| **优化后** | ✅ GPU | **512** | **19批** | **1-2分钟** |

**提速效果：**
- GPU开启：提速约2-4倍（vs CPU）
- batch_size增大：再提速约2倍（减少批次数）
- **综合提速：约4-8倍**

### 技术细节
**GPU利用率偏低（15%）原因：**
- 模型小：`all-MiniLM-L6-v2`（384维向量）
- batch_size小导致GPU未充分利用
- CPU瓶颈：文件I/O、数据库写入、实体检测

**为什么不是GPU 100%利用率：**
- Embedding模型轻量，GPU计算快但批次间隔有CPU工作
- 同步数据库写入期间GPU空闲
- 批次间有Python代码执行（实体提取、元数据构建）
