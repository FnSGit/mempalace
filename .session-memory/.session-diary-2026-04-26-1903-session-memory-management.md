# 会话日记 - 2026-04-26（Session Memory管理改进）

## 用户提出关键改进建议

**用户原话（verbatim）：** "我觉得这很重要，应该和Claude.md文件一样把这些重要决策加载进来。这样一开始就有了项目的跟踪信息，节省了再次项目探究，节省时间和token。再有，把文件放到根目录，这样很快根目录就炸了，需要一个目录统一管理。"

两个核心洞察：
1. **Session diary应该像CLAUDE.md一样自动加载**
2. **根目录需要统一管理，避免文件混乱**

## 改进方案设计

### 问题分析

**之前的问题：**
- `.session-diary-*.md`文件散落在项目根目录（5个文件）
- 新会话不自动加载历史记忆
- AI每次"全新开始"，需要重新探究项目
- 用户重复解释背景（浪费时间和token）

**用户期望：**
- SessionStart时自动注入最近的决策和改动
- 类似CLAUDE.md的作用（项目背景 + 最近进展）
- 节省探究时间和token
- 根目录整洁

### 实施方案

#### 1. SessionStart Hook（自动加载记忆）

**创建脚本：** `~/.claude/hooks/mempal-sessionstart-wrapper.sh`

**功能：**
- 查找最近的2个`.session-diary-*.md`文件（按修改时间）
- 提取关键内容：
  - 最近一次：前100行（关键决策、代码改动）
  - 上一次：前50行（摘要）
- 输出到`.claude/session-memory/session-start-memory.md`
- Claude Code自动注入到system prompt

**验证效果：**
```bash
~/.claude/hooks/mempal-sessionstart-wrapper.sh
```

输出示例：
```markdown
# SessionStart - Project Memory Injection

## 最近会话历史（自动加载）

### 最近一次会话 (.session-diary-2026-04-26-memory-system-investigation.md)

## 核心问题追踪

### 问题1：电脑持续响声 - 高负载进程
发现活跃进程：PID 108966, 70.2% CPU...

**用户原话：** "根据上次的更改不是已经开启GPU加速了吗"
验证结果：✅ GPU确实已正确工作...

### 关键决策
1. batch_size优化：256 → 512
2. 配置SessionStart hook...
```

#### 2. 统一目录管理（保持根目录整洁）

**创建目录：** `.claude/session-memory/`

**改进Stop Hook：** `~/.claude/hooks/mempal-save-wrapper-v2.sh`

**功能：**
- 调用原始保存hook（生成`.session-diary`）
- 等待1秒确保文件完全写入
- 自动移动到`.claude/session-memory/`
- 记录管理日志

**文件迁移：**
```bash
mkdir -p .claude/session-memory/
mv .session-diary-*.md .claude/session-memory/
```

**效果对比：**
```
修改前：17个根目录文件（包含5个session diary）
修改后：12个根目录文件
减少：5个文件 ✓ 根目录整洁
```

#### 3. Git配置（避免提交临时文件）

**修改文件：** `.gitignore`

```gitignore
# Session diary files (managed by hooks)
.claude/session-memory/

# MemPalace user-specific data
.mempalace-link
```

**原因：**
- Session diary是临时文件，每次会话自动生成
- 不需要提交git（用户本地管理）
- 类似`.mempalace-link`（用户特定数据）

#### 4. 配置生效

**修改文件：** `~/.claude/settings.json`

**新增SessionStart配置：**
```json
{
  "hooks": {
    "SessionStart": [{
      "matcher": "*",
      "hooks": [{
        "type": "command",
        "command": "$HOME/.claude/hooks/mempal-sessionstart-wrapper.sh",
        "timeout": 30
      }]
    }],
    "Stop": [{
      "matcher": "*",
      "hooks": [{
        "type": "command",
        "command": "$HOME/.claude/hooks/mempal-save-wrapper-v2.sh",
        "timeout": 30
      }]
    }]
  }
}
```

## 设计架构

### 文件流转流程

```
新会话启动
↓
SessionStart hook触发
↓
查找最近2个.session-diary文件
↓
提取关键内容（100+50行）
↓
输出到session-start-memory.md
↓
Claude Code自动注入system prompt
↓
AI立即获得项目上下文

---

Stop hook触发（每15次对话）
↓
生成.session-diary-xxx.md（临时文件）
↓
wrapper等待1秒
↓
移动到.claude/session-memory/
↓
下次新会话可自动加载
```

### 与现有系统的关系

#### CLAUDE.md（项目长期文档）
- 提交到git，所有协作者共享
- 内容：设计原则、架构、命令、约定
- 加载时机：每次对话（always）

#### Session diary（最近进展）
- 不提交git，用户本地管理
- 内容：本次会话具体决策、改动、发现
- 加载时机：新会话启动（SessionStart）

**配合效果：**
```
CLAUDE.md：项目规范（长期、静态）
Session diary：最近进展（短期、动态）
↓
新会话同时加载
↓
AI既懂规范，又知道进展
↓
完美上下文，无需重复解释
```

#### MemPalace Palace（深度历史）
- 存储：`~/.mempalace/palace/`（878MB，27525 drawers）
- 搜索：`mempalace_search`（MCP工具）
- 层级：Layer 3（深度搜索，按需）

**设计意图：**
```
Layer 0（Identity）：用户身份（~100 tokens）
Layer 1（Essential Story）：Session diary（~600-900 tokens）← 本次实现
Layer 2（On-Demand）：按主题加载（~200-500 each）
Layer 3（Deep Search）：Palace全量搜索（unlimited）
```
