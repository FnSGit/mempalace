## 根本原因发现

**真相：这不是bug，是"silent rebuild"设计机制**

通过 git 历史追踪到关键提交 `7e5eeda`：

```
feat(normalize): auto-rebuild stale drawers via NORMALIZE_VERSION schema gate

v2 (2026-04): introduced strip_noise() for Claude Code JSONL; previous
              drawers stored system tags / hook chrome verbatim.
```

### 版本升级机制

**palace.py:54**
```python
NORMALIZE_VERSION = 2  # v1 → v2 升级
```

**palace.py:375-376**
```python
stored_version = stored_meta.get("normalize_version", 1)  # Pre-v2 默认是1
if stored_version < NORMALIZE_VERSION:  # 1 < 2
    return False  # 触发重挖
```

### 时间线还原

1. **昨天晚上**：处理 ~/.claude，数据存储为 version=1（或缺失）
2. **代码更新**：NORMALIZE_VERSION 升级到 2（新增 strip_noise()）
3. **今天运行**：hook触发 mine，检测到 version < 2
4. **自动重挖**：172个文件全部重建，应用新噪音清理规则
5. **实际结果**：
   - Files processed: 172
   - Files skipped: **只有1个**
   - Drawers filed: 27525

### 设计意图（verbatim from commit）

**提交说明原文：**
> "Without this, the strip_noise improvement only helps new mines. Every user who had already mined Claude Code JSONL sessions would keep their noise-polluted drawers forever, because convo_miner's file_already_mined skip short-circuits before re-processing."

**解决方案：**
> "Adds a versioned schema gate so upgrades propagate silently — file_already_mined now returns False if the stored normalize_version is missing or less than current, triggering a rebuild on next mine."
